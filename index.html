CAW — Ethereum EditionCAW — Ethereum 版Coming Soon近日公開

A decentralized social network that spans three chains — name NFTs on Ethereum, posts on Base, and an archive on Arbitrum, stitched together with LayerZero. An independent deployment of the Gilgamesh CAW design, run by the community, is on its way. Ethereum で名前 NFT、Base で投稿、Arbitrum にアーカイブ記録を持ち、LayerZero でつながる3チェーン構成の分散型 SNS。Gilgamesh 版 CAW の設計を、コミュニティが独立にデプロイする版がもうすぐ来ます。

How it works仕組み

Ethereum

Names名前

Your identity is an NFT name (CawProfile) minted on Ethereum L1. Each name carries its own CAW deposit balance.あなたの identity は Ethereum L1 で発行される NFT の名前（CawProfile）。名前ごとに CAW のデポジット残高が紐づきます。

Base

Posts投稿

You sign a post with EIP-712 — no L2 gas needed on your side. Validators submit it to CawActions on Base, where it becomes final on-chain.投稿は EIP-712 署名だけ。あなたの側に L2 のガスは要りません。バリデータが Base 上の CawActions へ提出し、チェーン上で確定します。

Arbitrum

Archiveアーカイブ

Actions are replicated to a dedicated archive chain, so the record of what happened survives independently of any single service.アクションは専用のアーカイブチェーンへ複製されます。ひとつのサービスに依存せず、起きたことの記録が残ります。

LayerZero · Node

Connected and self-run接続と自前ノード

LayerZero messages carry name syncs and archive replication between the chains. A self-run node — API, validator and indexer — reads the chains and serves the timeline.名前の同期やアーカイブ複製は LayerZero のメッセージが運びます。自前ノード（API・バリデータ・索引）がチェーンを読んでタイムラインを届けます。

Proven on testnetテストネットで実証済み

  • The full stack was deployed by the community on Sepolia, Base Sepolia and Arbitrum Sepolia一式をコミュニティが Sepolia／Base Sepolia／Arbitrum Sepolia に自前デプロイ済み
  • A name minted on L1 arrived on Base via LayerZero, deposit includedL1 で取得した名前が、デポジットごと LayerZero 経由で Base に届いた
  • A signed post was submitted by the node's validator and finalized on-chain署名した投稿を自前ノードのバリデータが提出し、オンチェーンで確定した
  • The post was read back through the node's own API — the full loop works投稿を自前ノードの API から読み戻せた — 通しの流れが機能している
  • Automated wiring verification passed on every check配線の自動検証は全項目を通過した

Run a node — beginner guideノードを立てる（初心者向け）

Anyone can run a node for this deployment — that is the point of the design. The initiator of this deployment deliberately does not operate a node: a network that only runs on its founder is not decentralized. We are waiting for the community to act. Two roles:このデプロイのノードは、誰でも立てられます。それがこの設計の要点です。そして発起人は、あえてノードを運営しません。発起人だけが動かすネットワークは、分散型とは言えないからです。コミュニティの行動を待ちます。役割は2つあります：

  • Read node (API + indexer): serves the timeline. Needs no keys at all読み取りノード（API＋索引）：タイムラインを届けます。鍵は一切不要です
  • Validator node: also submits signed posts on-chain (Base), and receives the CAW tip attached to every action it processes. Needs a name NFT and a small amount of Base ETH for gasバリデーターノード：署名済み投稿をチェーン（Base）へ提出し、処理した投稿のチップ（CAW）を受け取ります。名前NFTと、ガス代の少額の Base ETH が必要です

Steps:手順：

  • Step 1 — Get a VPS: Ubuntu 24.04, 2 GB RAM or more (about ¥1,259/month at ConoHa, payable at a convenience store or by bank transfer — no credit card needed; Oracle Cloud's free ARM tier also works but its signup needs a card)ステップ1 — VPS を用意する：Ubuntu 24.04、メモリ2GB以上（ConoHa なら月約1,259円、コンビニ払い・銀行振込OKでクレジットカード不要。Oracle Cloud の無料ARM枠でも動きますが、申込にカードが必要です）
  • Step 2 — Run the setup script (below): it installs Node.js 22, PostgreSQL, Redis and a firewall in one go, and is safe to re-runステップ2 — 構築スクリプト（下記）を実行する：Node.js 22 / PostgreSQL / Redis / ファイアウォールを一括で入れます。再実行しても大丈夫な作りです
  • Step 3 — Place the node code (the Caw repository's client/) and copy the env template, filling in the contract addresses listed on this page (updated when the rebuild completes)ステップ3 — ノードのコード（Caw リポジトリの client/）を置き、設定テンプレートをコピーして、このページに掲載する契約アドレスを入れる（作り直し完了後に更新します）
  • Step 4 — Run the deploy script: the node starts as a system service and gets a public URL through a Cloudflare tunnelステップ4 — 配置スクリプトを実行する：ノードが常駐サービスとして起動し、Cloudflare トンネルで公開URLが発行されます
  • Step 5 (validators only) — Put your own wallet key only in a file on your own server. Never send it to anyone or paste it into a chatステップ5（バリデーターのみ）— 自分のウォレットの鍵は、自分のサーバー上のファイルにだけ置く。他人に送らない・チャットに貼らないでください

Tools (free to use): Beginner guide (Japanese) · setup.sh · deploy-app.sh · env.templateツール一式（無料）： 初心者向けガイド · setup.sh · deploy-app.sh · env.template

Operators cannot forge or alter posts (every action carries its author's signature, verified on-chain), and running a node never gives custody of the protocol: the contract admin keys stay with their owners. Stuck? Ask in the community channels linked from the Guppy's Guide dashboard.運営者が投稿を偽造・改ざんすることはできません（投稿には発信者の署名があり、チェーン側で検証されます）。ノードを立てても契約の管理権は移りません。困ったら、Guppy's Guide ダッシュボードから辿れるコミュニティの窓口で声をかけてください。

Run a nodeノードを立てる

Anyone can run a node for this deployment — that is the point of the design. The initiator of this deployment deliberately does not operate a node: a network that only runs on its founder is not decentralized. We are waiting for the community to act. There are two roles:このデプロイのノードは、誰でも立てられます。それがこの設計の要点です。そして発起人は、あえてノードを運営しません。発起人だけが動かすネットワークは、分散型とは言えないからです。コミュニティの行動を待ちます。役割は2つあります：

  • Read node (API + indexer): serves the timeline. Needs no keys at all — just point the open-source node software at the published contract addresses and it syncs from the chains by itself読み取りノード（API＋索引）：タイムラインを届けます。鍵は一切不要で、オープンソースのノードを公開済みのコントラクトアドレスに向ければ、チェーンから自動で同期します
  • Validator node: also submits signed posts on-chain (Base). Needs a name NFT and a small amount of Base ETH for gas. In return, the validator receives the CAW tip attached to every action it processes — posters collectively fund the gas, so no single operator carries the networkバリデーターノード：署名済み投稿をチェーン（Base）へ提出する役割も担います。名前NFTと、ガス代の少額の Base ETH が必要です。代わりに、処理した投稿に付いたチップ（CAW）がバリデーターに入ります。ガスは投稿者みんなのチップでまかなわれるため、特定の運営者が抱え込む形にはなりません
  • What you need: a VPS (2 GB RAM or more), Ubuntu 24.04, Node.js 22, PostgreSQL and Redis. Setup scripts and a runbook are ready — ask in the community channels linked from the Guppy's Guide dashboard if you want to join必要なもの：VPS（メモリ2GB以上）、Ubuntu 24.04、Node.js 22、PostgreSQL、Redis。構築スクリプトと手順書は用意済みです。参加したい方は、Guppy's Guide ダッシュボードから辿れるコミュニティの窓口で声をかけてください
  • Operators cannot forge or alter posts (every action carries its author's signature, verified on-chain), and they never take custody of the protocol: the contract admin keys stay with their owners, separate from node operation運営者が投稿を偽造・改ざんすることはできません（投稿には発信者の署名があり、チェーン側で検証されます）。また、契約の管理権はノード運営とは別に所有者のもとに残ります
