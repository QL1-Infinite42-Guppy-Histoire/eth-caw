# ETH版 CAW — ノードの立て方（初心者向け）

**まず、専門用語なしで言うと**：サーバーというのは、ずっと電源が入りっぱなしの「借りるコンピューター」です。このアプリでは、みんなの投稿を運ぶ係をします。誰か1台でも動いていれば、利用者は何もしなくて大丈夫です。自分でも係を増やしたい人だけが立てるもので、やることは3つだけです：

1. **コンピューターを借りる**（レンタル屋さんは選べます：ConoHa 月1,259円〜／XServer VPS 月1,760円〜／さくらのVPS 月1,738円〜。どれも支払いはコンビニ・銀行振込で、カードは要りません）
2. **作るときに、文章を1つ貼る**（アプリの「サーバー」タブにあるボタンでコピーして、作成画面の大きな入力欄に貼るだけ。あとは全部自動です）
3. **あとは待つだけ**（15分ほどで、アプリが勝手に見つけてつながります）

**立てると、自分にどんないいことがある？**（「お金を払って損するだけ」ではありません）
- 自分のタイムラインが止まりません。他人のサーバーの都合で「今日は見られない」がなくなります
- 混まない自分専用線です。誰かがサーバーを止めても、あなたの分は動き続けます
- 他の人のサーバーを経由しないので、変な細工をされる心配がありません
- 次の段階（投稿をチェーンに届ける係）まで進むと、投稿した人から CAW のチップが入る仕組みがあります
- 台数が増えるほど全体が止まりにくくなり、自分の名前や投稿の居場所も守られます

月1,259円は「自分の分が止まらない保険」と考えると分かりやすいです。

以下は、その詳しい手順です。

このデプロイ（コミュニティによる独自デプロイ）のノードは、誰でも自分のサーバーで立てられます。
最初の公開ノードは 2026年11月12日 に発起人の VPS で稼働を始め、最初の投稿もチェーンに届きました。誰でも2台目になれます。コミュニティのノードを引き続き歓迎します。

## 一番かんたんな方法（ワンタッチ設置）

VPS を作るときに、**スタートアップスクリプト**の欄へ [install-node.sh](https://ql1-infinite42-guppy-histoire.github.io/eth-caw/node-kit/install-node.sh) の中身を丸ごと貼るだけです（ConoHa なら「スタートアップスクリプト」を選んで貼り付け）。サーバーが起動すると、インストールからノード起動・公開URLの発行まで全部自動で進みます。すでにサーバーがある場合は、root で次の1行でも同じです：

```
curl -fsSL https://ql1-infinite42-guppy-histoire.github.io/eth-caw/node-kit/install-node.sh | bash
```

終わったら、サーバーで `cat /opt/caw/node-url.txt` と打つと公開URLが出ます。ノードは自分のURLを公開ノード一覧へ自動で知らせるので、アプリは自動で見つけて接続します（自分のノードに固定したい場合は、アプリの「ノード」タブにそのURLを貼ってください）。手作業で1つずつ入れたい場合は、下の手順（setup.sh ＋ deploy-app.sh）もそのまま使えます。

## まず結論

- **読み取りノード**（タイムラインを届ける役）：秘密鍵は一切いりません。
- **バリデーター**（投稿をチェーンに確定する役）：自分のウォレットと自分の鍵で動きます。他人の鍵は不要ですし、私たちがあなたの鍵を受け取ることもありません。
- ノード運営者にできるのは「自分のノードに来た投稿を遅らせる・断る」まで。投稿の改ざんはできません（投稿は利用者の署名付きで、検証はチェーン側）。
- 契約の管理権はノード運営とは別に残ります。ノードを立てる＝管理権を持つ、ではありません。

## 必要なもの

| 役割 | 必要なもの |
|---|---|
| 読み取りノード | VPS 1台 ＋ このページのツール一式 |
| バリデーター | 上記 ＋ 自分のウォレット（Base ETH 少額＝ガス代）＋ 自分の名前NFT（チップの受け取り先） |

- サーバー代の目安：ConoHa VPS 2GB で月約1,259円（コンビニ払い・銀行振込・PayPal で前払い可、クレジットカード不要）。Oracle Cloud の無料枠（ARM）でも動きますが、申込にクレジットカードが必要です。
- ガス代（バリデーターのみ）：Base での投稿確定のガスをバリデーターが立て替えます。代わりに、処理した投稿1件ごとのチップ（CAW、既定1,000）がバリデーターに入ります。ただし現状の CAW 価格ではチップが実費を大きく下回ります（下記「補助モード」参照）。
- データはチェーンの写しなので、引き継ぎなしでゼロから同期し直せます。

## 手順

1. **VPS を用意する**（Ubuntu 24.04、メモリ2GB以上）。
2. **構築スクリプトを実行する**：`setup.sh` を root で実行すると、Node.js 22 / PostgreSQL / Redis / ファイアウォールが入ります（何度実行しても同じ結果になる作りです）。
3. **ノードのコードを置く**：CAW のリポジトリ（GilgameshCaw/Caw）の `client/` を `/opt/caw/Caw` に配置します。
4. **設定ファイルを置く**：`env.template` を `client/.env` にコピーし、DB パスワード（サーバー上の `/root/.caw-db-pass`）と、下記の契約アドレスを入れます。
5. **起動する**：`deploy-app.sh` を root で実行すると、systemd サービスとして常驻し、公開用 URL（Cloudflare トンネル）も発行されます。
6. **確認する**：API（:4000）が応答し、アプリの設定にその URL を入れると、そのノード経由でタイムライン表示・投稿ができます。
7. **バリデーターになる場合のみ**：同梱の `make-validator-wallet.sh` を**自分のサーバーで**実行します。ウォレットがサーバー上で生成され、秘密鍵はそのサーバー内の設定ファイルに直接書かれます（画面にも出ませんし、どこにも送信されません）。表示される公開アドレスに Base の ETH を少額（0.005 ETH 程度）送り、`systemctl restart caw-node` で再起動すれば、投稿を届けられるようになります。鍵を他人に送らない・チャットに貼らないでください。

## クライアント側の修正について（開示）

コントラクトには一切触れていません。一方、原典の**ノード用ソフト（クライアント）**は投稿の提出部分がテストネット前提で書かれており、無修正ではメインネットに1件も提出できません（チェーン番号がテストネットのままのため、送信がすべて弾かれます）。インストーラーは、キットが管理する修正として次の2点を明示的に適用します。どちらも、原典のソースに想定した文字列が正確に無ければ**止まる**作りです（勝手に読み替えないため）。

1. **チェーン番号の修正（常に適用）**：届け役の送信部分のチェーン番号をテストネット（84532）から Base 本番（8453）へ。規則も経済条件も変えません。
2. **補助モード（任意・既定はオフ）**：投稿1件の既定チップ 1,000 CAW は、2026年11月12日時点の実勢で約0.001円。一方、届ける実費（Base のガス＋LayerZero 手数料）は約0.36円で、釣り合うチップは約17万 CAW です。原典のままでは、届け役は「チップが実費未満」の投稿をほぼ全部断ります（それが原典の設計です）。`CAW_NODE_SUBSIDY=1` を付けて設置すると、**自分のノードだけ**そのチェックを外し、差額を運営者が被って届けます。投稿者が払う金額（投稿コスト＋チップ）はコントラクトが強制するので変わりません。他人のノードには影響しません。発起人のノードはこのモードで稼働しています。

## アプリへの自動接続（nodes.json）
